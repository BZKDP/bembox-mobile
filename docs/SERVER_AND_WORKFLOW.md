# Сервер и рабочий процесс

## Назначение серверного каталога

Handoff-копия мобильного проекта размещается отдельным каталогом внутри:

```text
/var/www/bem-dev.ru/sotrudniki/
```

Работающий backend использует PM2-процесс `sotrudniki` на порту `3025`, а Nginx-конфигурация находится в `/etc/nginx/sotrudniki.conf`. Мобильный каталог не является частью runtime backend: для передачи исходников не требуется рестарт PM2, reload Nginx или открытие нового порта.

## Подключение

```bash
ssh -p 22 root@<SERVER_HOST>
cd /var/www/bem-dev.ru/sotrudniki/bembox-mobile
```

Пароль/SSH-ключ передаётся отдельно по защищённому каналу и не должен сохраняться в этом файле, shell history или репозитории.

## Работа с копией

Серверная папка — архив передачи и источник для скачивания. Flutter-сборку Android удобнее выполнять на машине разработчика/CI, iOS — только на macOS/CI. Не устанавливайте Flutter, Xcode или Android SDK на production-сервер без отдельного решения администратора.

Скачать проект:

```bash
scp -P 22 -r root@<SERVER_HOST>:/var/www/bem-dev.ru/sotrudniki/bembox-mobile ./bembox-mobile
```

Лучший рабочий процесс:

1. клонировать канонический Git-репозиторий либо скачать handoff;
2. создать отдельную ветку;
3. выполнить изменения и локальные тесты;
4. открыть pull request;
5. собрать подписанный артефакт через защищённый CI;
6. опубликовать через кабинеты магазинов.

## Диагностика backend (только чтение)

Если мобильное приложение не загружает сайт или API, сначала проверить независимо:

```bash
pm2 status
pm2 logs sotrudniki --lines 100 --nostream
ss -ltnp | grep ':3025'
nginx -t
curl -I https://bembox.ru
```

Не перезапускайте PM2/Nginx только из-за изменения мобильных исходников. Рестарт нужен лишь при изменении соответствующего backend/config и должен выполняться отдельной контролируемой операцией с резервной копией.

## Обновление handoff-копии

Не копировать поверх без резервной копии. Рекомендуемый шаблон:

```bash
cp -a bembox-mobile "bembox-mobile.backup.$(date +%Y%m%d-%H%M%S)"
```

Затем передать новый архив, проверить SHA-256 и распаковать во временную папку. После проверки переименовать каталоги атомарно. Не применять `rm -rf` к корню проекта.
