# Известные особенности и технический долг

## Приоритет высокий

1. Android release при отсутствии `key.properties` автоматически использует debug signing. Лучше изменить Gradle так, чтобы release-сборка завершалась ошибкой без настоящего ключа.
2. Push `appVersion` захардкожен тремя разными значениями (`1.0.0`, `1.0.2`, `1.0.4`) вместо текущего `1.0.5+6`.
3. iOS запрашивает уведомления и в `AppDelegate`, и через FCM; запрос может появляться раньше завершения онбординга. Нужна единая точка запроса после понятного пользовательского контекста.
4. FCM и прямой APNs одновременно регистрируются на iOS. Backend должен выбрать основной маршрут либо дедуплицировать отправку.

## Сборочная система

- На проверенной машине Android build предупреждал о приближающемся прекращении поддержки Gradle 8.11.1, Android Gradle Plugin 8.9.1 и Kotlin 2.1.0 текущим Flutter. Обновлять связкой после тестовой сборки.
- Нативные зависимости требуют согласованную версию Android NDK; комментарий в `build.gradle.kts` о полном отсутствии native-зависимостей устарел.
- `flutter pub outdated` показывает много доступных обновлений. Не делать массовый major upgrade в одном релизе; особенно аккуратно с WebView, Firebase, Riverpod/GoRouter и RuStore Push.

## Анализатор

Среди них неиспользуемый `dart:async` в `crash_reporter.dart`, лишние null-aware выражения в API-коде, использование BuildContext после async gap в легаси cart и замечание к doc comment. Они не блокируют сборку, но должны быть разобраны перед ужесточением CI.

## Архитектура и поддержка

- В репозитории остаётся крупный неактивный fully-native Flutter UI. Нужно принять явное решение: сохранять как будущую ветку, вынести в архивную ветку или удалить после подтверждения владельца.
- `CrashReporter` не отправляет ошибки наружу. В production нет централизованной мобильной crash-аналитики.
- Cache-buster сайта `_siteRev = 20260622` меняется вручную. Лучше получать ревизию управляемо или добавить безопасную политику обновления.
- Android WebView debugging включён без проверки build mode. Для release желательно отключить.

## Функциональное тестирование перед релизом

- чистая установка и повторный запуск после онбординга;
- сохранение веб-сессии после обновления версии;
- offline/retry и восстановление после пустой страницы;
- Android back и внутренние SPA-маршруты;
- камера, галерея, микрофон и геолокация;
- звонок, email, внешняя оплата и возврат в приложение;
- RuStore/FCM/APNs во всех состояниях приложения;
- живой статус заказа и тап по нему;
- реальные устройства iPhone и Android разных OEM, а не только эмулятор.
